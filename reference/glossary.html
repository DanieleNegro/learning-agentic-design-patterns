Glossario

Un termine entra qui solo dopo che Daniele ne ha dimostrato la comprensione in un esercizio — non basta che sia stato "coperto" in una lezione.

Questo documento cresce lezione dopo lezione, in modo incrementale. Ogni riga cita la lezione in cui il termine è stato introdotto e verificato. Se in una lezione futura la comprensione di un termine si approfondisce o si corregge, la definizione qui viene aggiornata — non duplicata.

Concetti fondamentali

TermineDefinizioneConfermato in
Workflow Sistema in cui LLM e tool sono orchestrati attraverso predefined code paths — il flusso di controllo lo scrive chi progetta il sistema, non il modello. 0001
Agent Sistema in cui l'LLM dirige dinamicamente il proprio processo e l'uso dei tool, passo dopo passo, in un loop guidato dal feedback dell'ambiente. 0001

Pattern di workflow

TermineDefinizioneConfermato in
Routing Classifica l'input e lo instrada verso un solo handler specializzato fisso — un unico branch, deciso a runtime dal codice, non dal modello. 0001
Orchestrator-workers Un LLM centrale scompone dinamicamente il task e delega sotto-task a worker (Subagent) con contesto separato; il ciclo orchestratore→worker→sintesi resta codice fisso. 0001

Primitivi di Claude Code

TermineDefinizioneConfermato in
Hook Comando eseguito automaticamente a un evento fisso del ciclo di vita (es. PostToolUse) — gira sempre, indipendentemente da cosa "decide" il modello. 0001
MCP (Model Context Protocol) Protocollo standard aperto per collegare l'LLM a sistemi esterni — database, API, servizi — in modo uniforme. 0001
Subagent Agente delegato con proprio contesto separato, invocato dal main agent — la primitiva concreta dietro il pattern orchestrator-workers. 0001

Se una definizione qui ti sembra imprecisa, o vuoi un controesempio in più, chiedimelo — questo glossario è pensato per essere corretto nel tempo, non scritto una volta per sempre.
