Anatomia di una Skill: cosa entra in contesto, e quando

Lezione 0007 — primo capitolo sul secondo asse della mission, con un esempio che hai già sotto mano

Le lezioni 0001-0006 hanno coperto un solo asse della tua mission: i cinque pattern di workflow. Qui si comincia un asse diverso — le Skill, il meccanismo con cui estendi cosa Claude Code sa fare. Una Skill è un file SKILL.md con istruzioni: Claude lo aggiunge al proprio "toolkit" e lo usa quando è rilevante, oppure lo invochi tu direttamente con /nome-skill1.

1. Extend Claude with skills — Claude Code Docs, sezione introduttiva.

L'esempio non è astratto: è questa sessione

Non serve un esempio inventato: la skill che hai appena invocato scrivendo /teach è un caso reale, leggibile in .claude/skills/teach/SKILL.md in questa stessa repository. Il suo frontmatter YAML è: 

---
name: teach
description: Teach the user a new skill or concept, within this workspace.
disable-model-invocation: true
argument-hint: "What would you like to learn about?"
---

Sotto il frontmatter, il corpo in markdown contiene tutte le istruzioni che hai visto seguire in questa conversazione — come strutturare MISSION.md, come titolare una lezione, come usare il glossario. Questo è lo schema minimo di ogni Skill: frontmatter (che dice a Claude quando/come usarla) più contenuto markdown (le istruzioni vere e proprie)2.

2. Dei campi di frontmatter possibili, la documentazione è esplicita: "All fields are optional. Only description is recommended so Claude knows when to use the skill."

Progressive disclosure: tre livelli, tre momenti diversi

Il motivo per cui conviene una Skill invece di scrivere la stessa procedura in CLAUDE.md è un motivo di costo: "unlike CLAUDE.md content, a skill's body loads only when it's used, so long reference material costs almost nothing until you need it"3. 3. Extend Claude with skills, introduzione.

La description entra in contesto ad ogni sessione, sempre. Il corpo di SKILL.md entra solo quando la skill parte. I file di supporto — qui, i vari *-FORMAT.md che il corpo di teach/SKILL.md referenzia — entrano solo se e quando servono davvero.

Chi può invocarla: il campo che hai già visto

Di default, sia tu sia Claude potete invocare una skill: tu con /nome, Claude automaticamente quando la description combacia con la conversazione. teach ha invece disable-model-invocation: true — significa che solo tu puoi farla partire; Claude non la carica mai di sua iniziativa4. Ha senso: l'insegnamento è un workflow che vuoi scatenare tu, non qualcosa che deve succedere perché la conversazione "sembra" educativa.

4. Motivazione esplicita della documentazione per questo campo: "Use this for workflows with side effects or that you want to control timing" — l'esempio canonico citato è /deploy, ma vale altrettanto per un workflow stateful come questo.

Alla fine di questa lezione saprai: descrivere le due parti di un SKILL.md (frontmatter + corpo), spiegare perché una Skill costa meno di un CLAUDE.md equivalente, distinguere i tre momenti della progressive disclosure, e leggere disable-model-invocation per capire chi può invocare una skill specifica.
